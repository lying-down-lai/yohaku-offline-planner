# 余白 — オフライン・プランナー

スマートフォンのブラウザからインストールできる、端末内保存の予定・タスク管理PWAです。AndroidとiOSのホーム画面への追加を想定しています。ログイン、サーバー、有料APIは不要です。

## 実装済み

- タスクと固定予定の追加、編集、削除。ホーム画面から詳細未設定のタスクもすぐ保存できます。タスクの完了は確認ダイアログを経て記録します。
- タスク・予定に毎日、毎週、毎月、毎年の周期と間隔、終了日を設定できます。系列は1件として保存し、カレンダーと今日の流れには各回を表示します。繰り返しタスクの完了は回ごとに記録します。
- 作業時間・週末設定に沿って、未配置タスクを空き時間に自動配置します。固定予定と配置済みタスクを避け、期限を超える配置はしません。所要時間が不明または要確認のタスクは配置しません。
- Dexie / IndexedDBによる端末内保存、JSONバックアップと検証付き復元。
- 外部LLM向けの文章・画像用抽出プロンプトと、現在のタスク・予定から作る7日間の計画用プロンプト。返答を検証・プレビューしてから反映します。重複する予定は追加せず、不明な予定は「要確認」として保持します。
- 今日の流れに予定間の空き時間を表示します。睡眠の目安を設定でき、AIの睡眠案は確認が必要な仮予定として追加します。
- アプリ表示中、復帰時に確認するアプリ内リマインダー。通知配送は `NotificationDelivery` インターフェースに分離しています。
- マニフェスト、192px / 512pxアイコン、サービスワーカー、GitHub Pages向けワークフロー。

## 開発

Node.js 22以上とpnpm 11を使います。

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm build
```

ローカルでは `http://localhost:5173/` を開きます。PWA機能の確認にはビルド後に `pnpm preview` を使用します。アイコンを再生成する場合は `pnpm icons` を実行してください。

## GitHub Pagesへの公開

1. このフォルダをGitHubリポジトリのルートへ配置し、`main` ブランチにプッシュします。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. `.github/workflows/deploy.yml` がインストール・ビルド・公開を行います。リポジトリ名からViteの `base` を設定し、`<user>.github.io` のルートサイトも扱います。

公開URL: https://lying-down-lai.github.io/yohaku-offline-planner/

## 構成とデータの流れ

| 部分 | 役割 |
| --- | --- |
| React + TypeScript + Vite | 画面とビルド |
| vite-plugin-pwa | マニフェスト、アセットの事前キャッシュ、サービスワーカー |
| Dexie + IndexedDB | 項目・設定・表示済みリマインダーの端末内保存 |
| `src/scheduler.ts` | UIやブラウザに依存しない純粋な自動配置ロジック |
| `src/todayFlow.ts` | 今日の予定と空き時間の計算 |
| `src/recurrence.ts` | 1件の系列から各回を計算する純粋なロジック |
| `src/planning.ts` | AI計画用プロンプトと提案の検証 |
| Zod (`src/transfer.ts`) | AI JSONとバックアップの形式検証 |
| date-fns | 日付の表示とスケジュール計算 |

自動配置は期限が早いタスクを先に扱い、同じ期限なら重要度が高いものを先にします。15分単位で開始位置を探し、指定作業時間内で1件を連続した枠に収めます。固定予定・既配置タスク・新規配置済みタスクとの衝突を避けます。30日以内に枠がない場合は未配置に残します。既存の配置や完了状態は自動変更しません。

繰り返しタスクは該当日の作業時間内へ回ごとに配置します。月末や2月29日など該当日が存在しない月・年はその月・年の最終日になります。繰り返しの編集・削除は系列全体に適用されます。製品方針と未実装の段階は `PRODUCT_PRINCIPLES.md` にまとめています。

## AI計画の使い方

「ツールと設定」で睡眠の目安を選び、「現在の予定から計画用プロンプトをコピー」を押します。任意の外部AIに貼り付け、返ってきた計画JSONをアプリへ戻してください。「提案を検証して確認」で内容を表示し、問題なければ反映します。タスク名・メモ・予定を外部AIへ送るかどうかは利用者が決めます。AIの睡眠枠は仮予定として要確認になります。

## 制約と次の段階

- データはブラウザとオリジンごとに分かれます。ブラウザのデータ削除や端末変更に備えて、JSONバックアップを保存してください。バックアップには個人情報が含まれ得るため、リポジトリに追加しないでください。
- リマインダーはアプリが開いているとき、およびアプリに戻ったときに確認します。バックグラウンド実行を前提にしていません。
- Web Pushは未実装です。将来必要なら配送インターフェースへ追加し、Cloudflare Workersと定期ジョブを任意のバックエンドとして導入できます。
- 同期、繰り返しの一回だけの編集・削除、タスク分割、複数端末共有は現時点の対象外です。
- 現行の自動配置とAI計画案は1タスクを1つの連続枠に置きます。長時間タスクの複数セッション化、実績と残り時間、未実行時の自動再計画は今後の課題です。製品方針と実装計画は `PRODUCT_PRINCIPLES.md` に記載しています。
